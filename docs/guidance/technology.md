# Technology guidance

Use the [common contract](../bootstrap.md). Select skills from actual stack evidence
in project manifests/configuration, with selection recorded in `handbook.json`.
Current reusable coverage is Next.js, React performance, web interface review and
Playwright tooling imported from Unibase. No other stack is assumed.

Installed framework documentation and official version-specific APIs resolve technical
questions; imported examples do not mandate dependencies, architecture or services.
Keep application facts, ownership, invariants and accepted adaptations in the project's
canonical documents. Preserve provenance and notices when updating imported material.
Add another technology only when a project needs it and there is a verified source.

## Applying technology skills

Use the authorized task, affected code, installed stack/version evidence and the
consumer's verification commands. Examples do not authorize dependencies or external
actions. Apply only the references relevant to the requested change; report changes
or findings, checks actually performed and unverified behavior. Review-only tasks
remain read-only. Scope, authority and local adaptations remain consumer-owned.

Next.js guidance owns framework conventions, API behavior and server/client correctness.
React performance guidance owns waterfalls, payloads, rendering and measured costs.
When both apply, load the relevant sections of each, not every bundled rule.
For version-sensitive claims, use installed documentation and official API references.
