# Voxr guidance adoption

## Outcome

Adopt the twelve selected Voxr practices in the Uniwares Handbook so maintainers
can review changes with shared evidence, hand off operational work, and upgrade
consumer guidance without losing local settings.

## Requirements and acceptance

| Requirements | Acceptance |
| --- | --- |
| V2, V3 | Large-work reviews share one current validation record. PR test flows are optional and give testers an observable result or an explicit environment limitation. |
| V5, V7 | Consumers can adopt a reviewed promotion conflict and rollback procedure. Authorized issue uploads distinguish local and host support and require remote readback before an ambiguous retry. |
| V8, V14 | The client guide defines versioned cases and a comparable sampling method for correctness, rework, prompts, tool calls, time and tokens. |
| V9, V15 | Claude workflow routing is opt-in. Sync preserves consumer settings. Refresh accepts an intact renamed-skill revision and retains its last good revision after an incomplete rename. |
| V10–V13 | Developer replies surface outcomes and decisions. Orchestration delegates bounded evidence work, resumes from actual state, and honors explicit approval for named unchanged actions. |

## Scope and authority

This delivery covers the Handbook. The Voxr chore is a separate draft for U1–U3.
The source revisions and individual adoption decisions live in
[provenance](../../../PROVENANCE.md#voxr-workflow-and-consumer-upgrade-adoption).
Live consumer adoption, publication, deployment and issue changes use their
existing authorities.
