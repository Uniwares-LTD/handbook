# Repository guidance

## Purpose

One or two sentences on what this repository does and who uses it.

## Commands

Link or list the commands for install, build, test and validation.

## Constraints

Invariants, terminology and rules that shared Handbook guidance does not cover.
Where a local rule differs from shared guidance, say which one applies and why.

For a hosting migration or retained fallback, link the accepted consumer decision
and identify the canonical repository. See the Handbook's
`docs/work-policy.md#repository-hosting-and-migration`.

## Templates

Issue and PR templates live in `.github`, and document templates in `docs/templates`.
They are permissive starting points: fill in what you know and skip, rename or delete
any section. Use the maintain-docs skill to add or refresh them. When a
template is missing here, use the shared starter (see the Handbook's docs/templates.md).

## Accepted exceptions

Local deviations that were agreed, with a short reason. Write "None" if there are none.

## References

Links to canonical documents. Link instead of copying their content.
